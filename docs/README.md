## Where to start

Install it and run a health check.
[Get started](get-started.md) covers installing, setting it up so it writes like your project, and the step most people skip: making sure it gets asked in the first place.

You do not need a command to use the plugin.
Describe what you want to document in plain words and it runs the right workflow.
The commands are shortcuts into those same workflows, and the [command reference](command-reference.md) has them if you want the full surface.

## What is not here

The plugin's own instruction files live under `skills/docs-assist/reference/` in the repository, not in this directory.
They are written for Claude rather than for you, and they change more often than these pages do.
[How the authoring loop works](how-the-loop-works.md) is the exception: it explains the drafting mechanism in reader-facing terms, and you only need it to judge what a draft's assumptions list is worth.

Project-level context lives at the repository root: [README](../README.md) for what the plugin is, [CHANGELOG](../CHANGELOG.md) for what changed, and [CONTRIBUTING](../CONTRIBUTING.md) for working on the plugin itself.
